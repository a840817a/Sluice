# Decrypted DASH AdaptationSets are rewritten in place

For a DASH channel in decrypt mode, Sluice decides per Period and AdaptationSet: when every Representation's `tenc` KID has a content key and the scheme is `cenc` or `cbcs`, it stores the AdaptationSet clear; otherwise it stores it as the origin produced it. The init is rewritten as a clear one (the encrypted sample entry takes its `frma` format; `sinf` and `pssh` are dropped), and each segment is decrypted where its samples lie in `mdat`. The boxes in `moof` that only describe the encryption (`senc` and its PIFF form, `saiz`, `saio`, `pssh`) keep their size but are retyped to `free`. We chose this over remuxing because a segment then keeps its length and every box its offset, so `trun` data offsets, `sidx` entries and SegmentBase byte ranges stay valid with nothing recomputed.

Keys added later convert an AdaptationSet already stored as ciphertext: a clear copy is written to a staging directory and swapped in with two renames. Its segment and init URLs gain `?c=1` so no cache serves the old bytes, and players that loaded it encrypted must reload. A wrong key cannot be detected: AES-CTR and AES-CBC decrypt any bytes without error, so a mistyped key yields unplayable segments, not a failure.
